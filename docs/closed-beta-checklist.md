# Nomad Wallet — Closed Beta Checklist

## Phase One

This checklist defines the **minimum responsible steps** required to run a closed beta for Nomad Phase One. It prioritizes user safety, clear expectations, and clean feedback loops.

---

## 1. Beta Scope Definition (Required)

Before inviting users, confirm:

* [ ] Beta is clearly labeled **“Phase One / Closed Beta”**
* [ ] No marketing language promising future features
* [ ] No implication of custody, insurance, or guarantees
* [ ] White paper is available to all beta users

**Goal:** Users understand what Nomad is — and what it is not.

---

## 2. Beta User Selection (Required)

Invite users who:

* [ ] Understand basic crypto concepts
* [ ] Are comfortable with non-custodial risk
* [ ] Are willing to give written feedback
* [ ] Will not store life-changing funds

Avoid users who:

* Expect instant support or recovery
* Want automated trading or DeFi dashboards

**Recommended size:** 20–100 users

---

## 3. Funding Guidelines (Critical)

Provide explicit guidance:

* [ ] Recommend small initial deposits
* [ ] Encourage test transactions first
* [ ] Cap travel prefunding (suggested: <$500 equivalent)
* [ ] Remind users that recovery loss = permanent loss

**Goal:** Prevent irreversible mistakes during beta.

---

## 4. Feature Flags & Limits (Required)

Ensure the following are enforced:

* [ ] Travel Mode off by default
* [ ] NFC off by default
* [ ] Daily / regional spending limits active
* [ ] Rate limits on unlock attempts
* [ ] Clear mainnet vs testnet indicators

**No hidden or experimental features enabled silently.**

---

## 5. Onboarding & Education (Required)

Verify:

* [ ] First-run clock tutorial is enabled
* [ ] Recovery setup is mandatory before use
* [ ] Permission explanations appear before OS prompts
* [ ] Confidence checklist is shown

Users should feel **calm, not rushed**.

---

## 6. Feedback & Logging (Recommended)

Set up:

* [ ] In-app feedback channel or link
* [ ] Anonymous issue reporting option
* [ ] Non-invasive error logging (no keys, no secrets)
* [ ] Clear instructions on what feedback is useful

**Never log:**

* Private keys
* Clock times
* Recovery data

---

## 7. Incident Response Plan (Required)

Prepare:

* [ ] Clear instructions for lost device scenarios
* [ ] Clear instructions for freezing travel mode
* [ ] Honest statement: no recovery without user materials
* [ ] Internal checklist for responding to security reports

**Goal:** Calm containment, not panic.

---

## 8. Legal & Ethical Clarity (Required)

Ensure:

* [ ] Disclaimer visible in app and repo
* [ ] Beta terms acknowledged by users
* [ ] No financial advice language
* [ ] No promises of future value or tokens

---

## 9. Exit Criteria (Important)

Define in advance:

* [ ] What ends Phase One beta
* [ ] What feedback triggers changes
* [ ] What issues block public release
* [ ] What moves to Phase Two

**Never let a beta drift without criteria.**

---

## 10. Final Go / No-Go Check

Before sending invites:

* [ ] White paper committed to repo
* [ ] README up to date
* [ ] Threat model documented
* [ ] Worst-case scenarios reviewed
* [ ] Team agrees on scope

If all boxes are checked, Nomad Phase One is **responsibly ready** for a closed beta.

---

> *A good beta protects users first and egos last.*
